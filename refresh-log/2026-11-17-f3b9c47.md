Upstream subject: Clarify local hostname blocking on shared IP addresses (#26626)

**Decision: material.** Rule applied: material 5.

The commit adds a 'Hostname blocking limitations' subsection inside 'Allow or block a destination' in local/network-rules.md, the heading that L1-S3-3 cites. The new text says that in local sandboxes a denied host that shares an IP address with an allowed host can still be reached. Three cases are listed: undecrypted connections whose inner Host or :authority isn't checked, later requests on a reused cleartext connection, and connections that name no host. This limits L1-S3-3, which says a deny blocks the destination even when a group or kit allows it. It also limits L1-S1-1 and L1-S1-4, which say a deny from any source overrides an allow. The matching addition to reference/network-rules.md says host decisions apply to the hostname attributed to the connection, which qualifies the same claims.
